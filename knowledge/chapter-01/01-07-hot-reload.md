# 1.7 Hot Reload, Hot Restart — принципы работы

## Что такое Hot Reload и Hot Restart?

Flutter предоставляет два механизма мгновенного обновления кода во время разработки:

| | Hot Reload | Hot Restart |
|---|---|---|
| **Что делает** | Обновляет исходный код в запущенном процессе | Перезапускает приложение с нуля |
| **Состояние** | Сохраняется | Сбрасывается |
| **Скорость** | Мгновенно (< 1 секунды) | Быстро (1-2 секунды) |
| **Когда использовать** | Изменение UI, логики | Изменение main(), initState(), зависимостей |

## Hot Reload — как это работает

### Принцип работы

```
1. Изменение кода в редакторе
        ↓
2. Dart Compiler компилирует изменённые классы
        ↓
3. Новые классы загружаются в Dart VM (JIT)
        ↓
4. Framework перестраивает Widget Tree
        ↓
5. Render Object Tree обновляется инкрементально
        ↓
6. Экран обновляется — состояние сохранено!
```

### Что Hot Reload может обновить:
- ✅ Изменение виджетов (текст, цвета, размеры)
- ✅ Изменение логики build()
- ✅ Добавление/удаление виджетов
- ✅ Изменение стилей и тем
- ✅ Изменение бизнес-логики

### Что Hot Reload НЕ может обновить:
- ❌ Изменение `main()` функции
- ❌ Изменение `initState()` (состояние не сбросится, но метод не вызовется заново)
- ❌ Изменение типов (нужен Hot Restart)
- ❌ Изменение структур данных, которые уже инициализированы
- ❌ Изменение зависимостей в pubspec.yaml

## Hot Restart — как это работает

Hot Restart полностью перезапускает приложение:

```
1. Изменение кода в редакторе
        ↓
2. Dart VM останавливает текущий процесс
        ↓
3. Приложение перезапускается с нуля
        ↓
4. Вызывается main()
        ↓
5. Создаётся новый Widget Tree
        ↓
6. Состояние сброшено, приложение в начальном состоянии
```

### Когда нужен Hot Restart:
- Изменение `main()` функции
- Изменение `initState()`
- Изменение структуры данных
- Изменение `const` констант
- Изменение зависимостей

## JIT vs AOT компиляция

### JIT (Just-In-Time) — для разработки

```
Dart код → JIT компилятор → машинный код (во время выполнения)
```

- Используется в **Debug** и **Profile** режимах
- Позволяет Hot Reload — классы можно подменять на лету
- Быстрая итерация разработки
- Немного меньшая производительность

### AOT (Ahead-Of-Time) — для релиза

```
Dart код → AOT компилятор → машинный код (до запуска)
```

- Используется в **Release** режиме
- Вся приложение компилируется в нативный ARM-код
- Нет JIT — Hot Reload невозможен
- Максимальная производительность
- Меньший размер бандла

## Жизненный цикл при Hot Reload

```
До Hot Reload:
  Widget A (состояние: count = 5)
    └── Widget B
  
Изменение кода → Hot Reload
  
После Hot Reload:
  Widget A (состояние: count = 5) ← СОХРАНЕНО!
    └── Widget B (обновлённый)
```

## DevTools — инструменты отладки

Flutter DevTools — набор инструментов для отладки:

```bash
# Запуск DevTools
flutter pub global activate devtools
flutter pub global run devtools
```

**Возможности DevTools:**
- **Widget Inspector** — исследование дерева виджетов
- **Performance** — мониторинг FPS, CPU, memory
- **Timeline** — детальный анализ кадров
- **Memory** — анализ утечек памяти
- **Network** — мониторинг сетевых запросов
- **Logging** — просмотр логов приложения

## Ограничения Hot Reload

### Когда Hot Reload не работает:

1. **Изменение структуры класса** — добавление/удаление полей
2. **Изменение типа переменной** — `int` → `String`
3. **Изменение `main()`** — точка входа
4. **Изменение `initState()`** — метод не вызовется заново
5. **Изменение `const`** — константы не обновляются
6. **Изменение `static` полей** — статические данные не сбрасываются

### Решение:
- Использовать **Hot Restart** (`R` или `Cmd/Ctrl + Shift + F5`)
- Перезапустить приложение полностью

## Заключение

Hot Reload — одна из главных фишек Flutter, которая значительно ускоряет разработку:
- **Hot Reload** — для быстрых итераций UI
- **Hot Restart** — когда нужно сбросить состояние
- **DevTools** — для глубокой отладки

Использование этих инструментов — ключ к продуктивной Flutter-разработке.
